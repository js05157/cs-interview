# 구현 계획

기존 두 저장소에 100개 주제 목록, 초기 10개 문서와 실행 가능한 게시 시스템을 구축합니다. AI API 없이 동작하며 예약은 비활성 상태로 유지합니다.

| 단계 | 작업 | 완료 판단 |
| --- | --- | --- |
| 1 | 환경·저장소 조사 | 공개/비공개, master, 기존 파일, 인증 확인 |
| 2 | 구조 설계 | 데이터와 오류 복구 경계를 ARCHITECTURE에 기록 |
| 3 | 100개 주제 | 분야별 개수, 중복, 선행 순서 검증 |
| 4 | 초기 10개 문서 | 필수 절, 꼬리 질문, 코드와 링크 검증 |
| 5~6 | GitHub·Notion | 모의 테스트로 중복·부분 성공·재시도 검증 |
| 7 | Jekyll 블로그 | 실제 빌드와 프로젝트 경로 링크 검사 |
| 8~9 | 통합·복구 | 상태 예약, 실패 플랫폼 재처리, dry-run 검증 |
| 10 | 나머지 90개 문서 | 10~20개씩 작성·검증·비공개 저장 |
| 11 | 승인 후 실연동 | 읽기 전용 dry-run → 승인된 샘플 → 별도 승인 후 예약 |

실제 검증 결과는 PROGRESS.md와 비공개 generation_checkpoint를 기준으로 확인합니다. 계획과 실적을 구분합니다.
