# 개인 개발자 블로그 개편 계획

## 승인·보존 범위

개인 블로그 화면 개편, 기존 첫 글의 설명형 재편집·같은 Notion 페이지 갱신·사이트 배포는 사용자 요청 범위입니다. 신규 CS 공개와 예약 활성화는 승인되지 않았습니다. 첫 topic ID, 2026-10-27 게시일, /topics/os-process-thread/ URL과 Notion 페이지 ID를 유지합니다. publication_policy의 첫 ID 제한과 워크플로우 게이트를 확대하지 않습니다.

100개 원문은 비공개 Git 기준점과 EDITORIAL_BASELINE에 보존하고 기존 글을 기반으로 배치 편집합니다. topic catalog·queue·코드·참고 링크는 유지·검증하며 새 글을 처음부터 생성하지 않습니다. 기존 면접형 검증 정책은 설명형 문서 검증으로 이전합니다.

## 정보 구조·표현

- 홈: 실제 소개 → GitHub 공개 프로필 활동 snapshot → 최근 글 → 검증한 프로젝트 → SSAFY 진입.
- 상단: 홈 / 글 / 프로젝트 / SSAFY. CS 10분야는 내부 메타데이터로만 보존.
- 글: content_type(cs/development/project/ssafy/essay) 필터와 작은 검색. CS와 직접 작성 글의 소스·대기열 분리.
- 본문: 적정 폭·접힌 목차·코드 복사·원본 SVG와 확대·alt·라이트/다크·키보드 지원. 기존 /about/, /learning/ 링크도 호환 진입으로 유지.
- SSAFY: 사용자가 밝힌 16기 구미 Java 전공반 정보와 종류별 작성 규칙. 존재하지 않는 활동·프로젝트 성과를 만들지 않음.

## 관리 방식

별도 인증 서버·유료 서비스·브라우저 PAT 없이 GitHub 편집기를 사용합니다. 공개 /manage/는 작성·목록·수정·삭제·이미지 업로드의 GitHub 동선이며 CMS라고 부르지 않습니다. GitHub 서버가 로그인·저장소 쓰기 권한을 확인합니다. 일반 방문자는 master를 직접 수정할 수 없습니다. 인증 권한을 프런트엔드 계정명 비교로 구현하지 않습니다.

직접 작성한 글은 blog/_posts의 content_type과 published 필드로 관리합니다. GitHub 미리보기를 사용하며 공개 저장소의 비노출 초안도 소스는 공개임을 명확히 안내합니다. 업로드 이미지는 blog/assets/uploads에 저장합니다. 일반 글은 CS 큐·Notion 동기화 대상에 넣지 않습니다.

## 관리 CS 글의 개정·공개 중단

현재 엔진은 본문 hash 변경과 이전 Notion fingerprint를 충돌로 중단하므로 직접 덮어쓰면 복구할 수 없습니다. 개정 계획에 이전 hash·새 hash·기존 Notion page ID·이전 관리 chunk 목록을 고정하고 동일 ID의 개정만 허용하는 절차를 구현합니다.

1. 공개된 기존 원문과 원래 state를 백업·검증한 뒤 개정 후보를 준비.
2. 같은 ID·날짜·경로에 새 원문·Jekyll·새 hash를 함께 기록. Notion·Pages는 새 버전 미완료로만 표시.
3. Notion 기존 페이지를 조회해 신·구 관리 chunk와 수동 블록을 구분. 새 내용부터 확인하고 허용된 이전 관리 chunk만 archive. 응답 유실은 marker 재조회로 조정하며 임의 새 페이지를 만들지 않음.
4. 동일 SHA에서 빌드·배포하고 receipt로 상태 완료. 중간 실패 시 같은 개정부터 복구하고 신규 ID를 선택하지 않음.

CS 공개 중단은 tombstone을 유지하여 재생성을 막고 Notion을 자동 삭제하지 않습니다. 현재 첫 글에는 공개 중단을 실행하지 않습니다. 실제 Notion 개정 전에 mock으로 혼합 상태·응답 유실·수동 블록 보존·동일 ID 재실행을 검증합니다.

## 단계와 검증

1. 분석·보존 기준점·이 설계 저장.
2. UI·활동 snapshot·직접 작성 구조 구현, 기존 첫 글 본문은 아직 변경하지 않음.
3. 설명형 validator·시각자료·첫 글 개정과 안전한 동기화 테스트.
4. 관리 동선·공개 중단 정책 테스트.
5. 나머지 99개 맥락 검토·배치 편집·코드/출처/도식 영수증 저장.
6. Python·실제 Jekyll·baseurl/자산·데스크톱/모바일·검색/키보드·Actions dry-run·동일 첫 글 개정 배포·Notion 재조회 검증.

GitHub workflow 수정 권한은 기존 개발 인증에 없으므로 기존 workflow가 호출하는 Python 경로를 우선 호환합니다. 실제로 workflow 변경이 꼭 필요해지면 파일과 검증 결과를 준비한 뒤 웹 등록 절차만 별도 보고합니다. CONTENT_REPO_TOKEN의 읽기 권한은 유지합니다.
