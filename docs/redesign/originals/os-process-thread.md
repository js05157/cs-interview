# 프로세스와 스레드

## 1. 핵심 개념

프로세스는 실행 중인 프로그램과 그 실행에 필요한 자원 및 상태를 묶은 운영체제의 추상화입니다. 스레드는 프로세스 안에서 실행 흐름을 구성합니다. 여러 요청을 동시에 처리하면서 자원 공유와 격리를 조절하기 위해 구분합니다.

일반적인 네이티브 스레드는 프로그램 카운터, 레지스터 상태, 스택을 각각 갖습니다. 같은 프로세스의 스레드는 힙과 전역 데이터, 열린 파일 같은 자원을 공유합니다. 여기서는 일반적인 OS 스레드를 기준으로 설명하며 JVM의 모든 실행 모델이 OS 스레드와 일대일인 것은 아닙니다.

## 2. 동작 원리

1. 프로세스 생성 시 운영체제는 주소 공간과 실행 상태를 준비합니다.
2. 스레드를 만들면 실행 위치와 별도 스택이 준비됩니다.
3. 스케줄러가 실행 가능한 스레드를 CPU에 배치합니다. 여러 코어가 있으면 병렬 실행도 가능합니다.
4. 스레드들이 같은 힙 객체를 수정하면 실행 순서에 따라 결과가 달라질 수 있어 동기화가 필요합니다.

예를 들어 웹 서버의 요청 처리 스레드들은 같은 싱글턴 서비스 객체를 참조할 수 있습니다. 메서드의 지역 변수라는 이유만으로 그 변수가 가리키는 객체까지 스레드 전용이 되는 것은 아닙니다.

## 3. 기술적 특징

| 기준 | 프로세스 간 분리 | 같은 프로세스의 스레드 |
| --- | --- | --- |
| 주소 공간 | 보통 독립, 명시적 공유 가능 | 힙 등을 공유 |
| 통신 | 소켓, 파이프, 공유 메모리 등 | 공유 객체와 동기화 |
| 장애 영향 | 격리 경계를 만들기 쉬움 | 메모리 훼손 등은 프로세스 전체에 영향 가능 |

스레드가 항상 더 빠르다는 결론은 피합니다. 공유의 편리함에는 경쟁과 장애 전파 비용이 따릅니다.

## 4. 코드 예시

```java
import java.util.concurrent.atomic.AtomicInteger;

public class ProcessThreadDemo {
    public static void main(String[] args) throws InterruptedException {
        AtomicInteger count = new AtomicInteger();
        Runnable work = () -> {
            for (int i = 0; i < 10000; i++) count.incrementAndGet();
        };
        Thread a = new Thread(work);
        Thread b = new Thread(work);
        a.start(); b.start();
        a.join(); b.join();
        if (count.get() != 20000) throw new AssertionError(count.get());
        System.out.println(count.get());
    }
}
```

두 스레드는 하나의 `count` 객체를 공유합니다. 원자적 증가를 사용하고 `join()`으로 종료를 기다립니다. 이 예제는 결과의 정확성을 확인하며 병렬 실행 여부나 처리 속도를 측정하지 않습니다.

## 5. 실무 활용

요청마다 스레드를 무한 생성하기보다 처리량과 대기 자원에 맞게 동시성을 제한합니다. 공유 서비스에는 요청별 가변 상태를 필드로 저장하지 않는 설계를 우선합니다. 강한 장애 격리가 필요하면 별도 프로세스나 서비스 경계를 검토합니다.

## 6. 기술 면접 답변

### 30초 답변

프로세스는 실행 자원과 주소 공간을 묶는 단위이고, 스레드는 그 안의 실행 흐름입니다. 같은 프로세스의 스레드는 힙을 공유하지만 각자 스택과 실행 상태를 가집니다. 그래서 통신은 편하지만 공유 데이터의 동기화를 고려해야 합니다.

### 1분 답변

웹 서버를 예로 들면 여러 요청 스레드가 같은 서비스 객체를 사용할 수 있습니다. 이때 공유 필드를 수정하면 경쟁이 생기므로 불변 객체나 동기화를 선택합니다. 프로세스를 분리하면 장애 격리를 강화할 수 있지만 통신과 운영 비용이 생깁니다. 저는 동시성뿐 아니라 공유 범위와 장애 경계를 함께 설명하겠습니다.

## 7. 예상 꼬리 질문

### 스택이 따로 있으면 무조건 안전한가요?

아닙니다. 스택의 지역 참조가 같은 힙 객체를 가리킬 수 있습니다. 참조의 위치와 객체의 공유 여부를 구분합니다.

### 단일 코어에서도 동시성이 가능한가요?

실행을 번갈아 진행하는 동시성은 가능합니다. 같은 순간 여러 명령 흐름을 실행하는 병렬성과 구분합니다.

### 프로세스는 메모리를 공유할 수 없나요?

공유 메모리 같은 명시적 수단을 사용할 수 있습니다. 독립 주소 공간이라는 기본 모델을 절대적인 공유 불가로 해석하면 안 됩니다.

## 8. 자주 하는 오해

- 스레드 수가 늘면 처리량도 비례한다: CPU와 락, DB 연결 등의 한계가 있습니다.
- 싱글턴은 스레드 안전하다: 생성 개수와 가변 상태 보호는 별개의 문제입니다.

## 9. 핵심 요약

- 자원 격리와 실행 흐름을 구분해 설명합니다.
- 공유 객체, 동기화, 장애 범위를 함께 검토합니다.
- 연관 키워드: 컨텍스트 스위칭, 뮤텍스, Java 메모리 모델.
