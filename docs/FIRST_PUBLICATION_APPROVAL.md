# 첫 1건 실제 게시 승인과 사전 점검

사용자는 2026-10-27 첫 주제 `os-process-thread`의 수동 게시와 결과 확인만 승인했습니다. 다른 주제 게시와 CS_AUTO_PUBLISH 활성화는 승인하지 않았습니다.

`config/publication_policy.json`은 승인한 ID 한 개와 대상 Notion 부모 페이지의 기대 식별자·제목을 저장합니다. 부모 식별자는 목적지 확인 정보이며 API 키를 저장하지 않습니다. 이후 게시 범위를 늘리려면 별도 사용자 승인이 필요합니다.

실제 publish의 prepare 단계는 공개 학습 파일 생성·push 전에 다음을 수행합니다.

1. 읽기 전용 후보 조회로 승인한 ID인지 확인합니다.
2. Actions에 전달된 NOTION_API_KEY로 users/me를 조회합니다. 응답의 개인 정보와 키는 출력하지 않습니다.
3. NOTION_PARENT_PAGE_ID와 승인된 CS 학습 부모의 ID·제목을 비교하고, 삭제·보관 상태를 검사합니다.
4. 이번 글의 실제 목적지인 운영체제/Process 계층을 생성하거나 재사용합니다. 새 페이지 생성 성공 시 Insert content 권한을 실제로 확인한 것입니다. 기존 계층을 재사용했을 때는 새 생성 권한을 다시 증명했다고 기록하지 않습니다.
5. 성공한 뒤에만 첫 학습 원문·Jekyll 글·게시 상태를 준비하고 공개 Git에 push합니다.

사전 점검이 실패하면 학습 원문 공개를 진행하지 않습니다. 이미 시작한 계층 생성의 불확실성이 있으면 안전한 계층 메타데이터만 checkpoint로 저장하고 실패합니다. 실제 주제 본문과 Pages 배포는 다음 단계에서 처리합니다.

Notion은 읽기·갱신·삽입 기능 권한을 구분합니다. [공식 capabilities 문서](https://developers.notion.com/reference/capabilities). users/me 성공만으로 본문 생성 권한을 단정하지 않습니다.

동일 날짜 재실행 제한 외에도 승인 ID 목록이 추가 주제의 게시를 차단하므로, 날짜가 바뀌어도 승인 없는 두 번째 주제를 게시하지 않습니다. 이 제한을 임의로 제거하지 마세요.
