## 정의

트랜잭션은 여러 데이터 변경을 하나의 작업으로 묶는 경계입니다. ACID는 전체 적용·제약 유지·동시 실행의 격리·장애 후 보존이라는 네 성질을 설명합니다.

## 설명

송금의 출금만 성공하고 입금이 실패하면 잔액이 맞지 않습니다. 트랜잭션을 시작해 두 변경을 수행하고 성공하면 COMMIT, 실패하면 ROLLBACK으로 결과를 결정합니다.

원자성은 전체 적용 또는 취소, 일관성은 정해 둔 불변식과 제약의 유지입니다. 격리성은 다른 트랜잭션과 변경을 관측하고 충돌하는 규칙이며 지속성은 성공한 결과를 장애 뒤 보존하는 계약입니다. 일관성은 DB가 업무 규칙을 자동으로 알아내거나 분산 복제가 항상 최신이라는 뜻은 아닙니다.

한 DB의 롤백이 이미 보낸 이메일이나 외부 결제를 취소하지는 않습니다. 긴 트랜잭션의 락·버전 유지 비용과 외부 부작용의 결과 조회·중복 방지도 별도로 설계합니다.

## 적용 예시

PostgreSQL 17의 전용 스키마에서 출금과 입금을 묶고 롤백·커밋의 결과를 비교합니다. 실제 장애 뒤의 내구성이나 동시 송금 전체를 이 예제로 증명하지는 않습니다.

```sql
CREATE TABLE wallet (
    id integer PRIMARY KEY,
    balance integer NOT NULL CHECK (balance >= 0)
);
INSERT INTO wallet VALUES (1, 1000), (2, 1000);
BEGIN;
UPDATE wallet SET balance = balance - 100 WHERE id = 1;
UPDATE wallet SET balance = balance + 100 WHERE id = 2;
ROLLBACK;
DO $$ BEGIN
    ASSERT (SELECT balance FROM wallet WHERE id = 1) = 1000;
END $$;
BEGIN;
UPDATE wallet SET balance = balance - 100 WHERE id = 1;
UPDATE wallet SET balance = balance + 100 WHERE id = 2;
COMMIT;
DO $$ BEGIN
    ASSERT (SELECT balance FROM wallet WHERE id = 1) = 900;
    ASSERT (SELECT sum(balance) FROM wallet) = 2000;
END $$;
```

롤백과 정상 커밋의 결과를 확인합니다. 전원 장애 이후의 복구나 동시 송금까지 이 한 예제로 검증한 것은 아닙니다.

## 정리

트랜잭션은 함께 성공하거나 취소해야 할 데이터 변경을 묶습니다. ACID는 그 작업의 원자성·일관성·격리성·지속성을 구분해 설명합니다. 올바른 업무 제약과 경계는 개발자가 정의해야 합니다. DB 밖의 부작용이나 실제 장애 후 복구는 별도의 계약과 검증이 필요합니다.

<details class="cs-followup">
<summary>Q1. DB를 롤백하면 이미 발송한 이메일도 취소될까요?</summary>
<div class="cs-followup-answer">
<p>아닙니다. 이메일 같은 외부 부작용은 로컬 DB 경계 밖에 있어 별도 전달·보상·중복 방지 정책이 필요합니다.</p>
</div>
</details>

<details class="cs-followup">
<summary>Q2. 트랜잭션을 쓰기만 하면 잘못된 잔액 규칙도 자동으로 고쳐질까요?</summary>
<div class="cs-followup-answer">
<p>DB는 정의하지 않은 업무 규칙을 자동으로 알 수 없습니다. 제약과 갱신 로직, 격리 수준을 함께 올바르게 구성해야 합니다.</p>
</div>
</details>
