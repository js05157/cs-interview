# 시간 및 공간 복잡도

## 정의

복잡도는 입력 크기가 커질 때 필요한 연산과 메모리의 증가를 표현하는 방법입니다. 실행 시간을 초 단위로 예언하기보다 후보 알고리즘의 확장성을 비교하는 데 씁니다.

## 설명

무엇을 입력 크기로 세고 어떤 연산을 한 번으로 볼지 먼저 정합니다. 안쪽 반복이 i번이면 전체는 0+1+…+(n-1)번이고, 후보를 매번 절반으로 줄이면 로그 횟수가 됩니다. 중첩 루프 개수만 보고 차수를 정하면 안 됩니다.

O는 점근적 상한, Ω는 하한, Θ는 양쪽 경계를 말합니다. 최악 분석과 입력 분포가 필요한 평균 분석, 연산열의 비용을 나누는 분할 상환도 서로 다른 질문입니다.

공간은 입력·출력을 포함했는지 보조 공간만인지 명시합니다. 재귀는 총 호출 수와 동시에 쌓이는 깊이를 구분하며 긴 문자열 비교나 큰 정수 연산의 비용을 무조건 상수로 두지 않습니다. 같은 차수라도 메모리 접근과 할당 때문에 실제 속도는 달라질 수 있습니다.

## 적용 예시

Java 반복 횟수를 합 공식과 대조하는 기존 예제입니다. 입력 상한으로 계산량 후보를 줄인 뒤 실제 서비스에서는 별도로 지연을 측정해야 합니다.

```java
public class ComplexityDemo {
  static long steps(int n){long c=0;for(int i=0;i<n;i++)for(int j=0;j<i;j++)c++;return c;}
  public static void main(String[] args){
    for(int n=0;n<100;n++)assert steps(n)==(long)n*(n-1)/2;
    assert steps(100)==4950;
    assert steps(200)>3*steps(100);
  }
}
```

JDK 17에서 실제 반복 횟수와 합 공식을 대조합니다. CPU 시간 측정이나 JVM 최적화 비교는 수행하지 않는 연산 수 실험입니다.

## 정리

복잡도는 입력에 따라 자원 사용이 얼마나 커지는지 설명합니다. 어떤 연산과 공간을 세는지 정해야 수치에 의미가 있습니다. 상한·평균·분할 상환은 같은 보장이 아닙니다. 점근 분석으로 후보를 좁히고 실제 부하의 성능은 따로 측정합니다.

## 꼬리 질문

### Q1. 이중 반복문이면 무조건 n제곱 번일까요?

각 반복의 경계와 전체 이동 횟수에 따라 다릅니다. 안쪽 범위가 줄거나 포인터가 전체 실행에서 한 번만 지나가는 경우도 있습니다.

### Q2. 보조 공간 O(1)이면 반환하는 결과도 공간을 쓰지 않을까요?

보조 공간에서 입력과 출력을 제외했을 수 있습니다. 무엇을 포함한 공간 계산인지 명시해야 합니다.
